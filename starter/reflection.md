# Technical Reflection

The agent separates deterministic execution from conversational reasoning. Order lookup and customer profile retrieval are routed through Gateway MCP tools backed by API Gateway and Lambda because these operations need exact records, repeatable behavior, and auditable service calls. Refund processing is also delegated to Lambda because approval logic should be deterministic, versioned, and independently secured. Loyalty arithmetic is handled in AgentCore Code Interpreter so the calculation runs in a sandbox with explicit business rules instead of relying on natural-language math. The LLM remains responsible for intent interpretation, deciding which tool to call, summarizing tool outputs, and using the Knowledge Base RAG tool for policy and catalog questions where grounded language synthesis is useful.

The main technical challenge was cross-session memory retrieval. AgentCore Memory strategy responses may expose namespace configuration as the newer `namespaceTemplates` field or the legacy `namespaces` field, and some templates include `{sessionId}` even when the agent needs customer-level recall across sessions. The implementation resolves both field names, injects `{actorId}` with the request `customer_id`, maps strategy types into `customer_facts` or `customer_preferences`, and uses namespace-path lookup when a template contains a session variable. That keeps Session B recall focused on the customer while avoiding a hard dependency on one SDK response shape.

For production, the Gateway should not remain unauthenticated. The sample assumes development-time access, but an enterprise deployment should require OAuth2 or Cognito JWT authorization, least-privilege IAM roles, and scoped Lambda invoke permissions. Memory also needs lifecycle controls: token budgets, sliding-window pruning, summarization, and PII retention policies should prevent unbounded context growth. Finally, API Gateway and Lambda should enforce throttling, structured logging, alarms, and idempotency for refund calls so retries do not create duplicate financial actions.
